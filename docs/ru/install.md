# Установка ноды Nexora

Нода — это плоскость данных: агент без состояния, который терминирует
клиентский трафик и делает то, что велит панель. У него нет ни базы данных, ни
интерфейса управления, ни файла настроек, который стоило бы резервировать —
единственное его состояние — пара сертификатов. Так задумано: потерянная нода
заново регистрируется в панели и возвращается точно такой же, и ничего на ней не
нужно переносить или восстанавливать.

Устанавливать ноду с этой страницы почти никогда не приходится. **Панель ставит
ноды за вас**, и однострочная команда, которую она выдаёт, — поддерживаемый путь.
Здесь сначала подробно разобран он, а затем ручной — для случаев, до которых
панель не дотягивается.

## Требования

- Linux-сервер с systemd. Публикуются amd64, arm64, armv5/v6/v7, 386, s390x и
  riscv64.
- Доступ root.
- Исходящий доступ к панели и TCP-порт **62050**, доступный *со стороны панели*.
- Порты, на которых будут слушать назначенные этой ноде inbound'ы.

Собственный лицензионный ключ ноде не нужен. Лицензия панели ограничивает,
сколько нод она будет обслуживать.

## Обычная установка

Добавьте ноду в панели и скопируйте показанную команду:

```bash
curl -fsSL https://PANEL/install-node.sh | bash -s -- --panel PANEL --token TOKEN
```

Запустите её от root на новом сервере. Меньше чем за минуту она:

1. Определяет архитектуру и скачивает бинарник ноды **с вашей панели**, а не из
   интернета.
2. Обменивает `TOKEN` на клиентский mTLS-сертификат панели. Токен одноразовый и с
   истечением; панель гасит его этим же запросом, и больше он не сработает.
3. Генерирует собственный серверный сертификат и ключ ноды.
4. Пишет `/opt/nexora-node/config.json` и unit systemd, затем запускает службу.

Панель подключается, запоминает отпечаток сертификата ноды на первом же
соединении и дальше принимает только его — доверие при первом использовании. Нода
со своей стороны принимает только клиентский сертификат панели. Ничто другое в
интернете не сможет заговорить с портом 62050 так, чтобы пройти TLS-рукопожатие.

Что можно добавить к команде:

| Флаг | Действие |
| --- | --- |
| `--listen ADDR` | привязать управляющий API не к `0.0.0.0:62050` |
| `--binary-url URL` | взять бинарник не с панели |

Если у панели нет подготовленного бинарника для архитектуры этого сервера,
установка падает на шаге 1 с `node binary not provisioned`. Подготовьте его на
хосте **панели** и повторите — не переходите ради этого на ручную установку:

```bash
# на сервере панели
curl -fsSL -o /tmp/node.tar.gz \
  https://github.com/nexora-vpn/node/releases/latest/download/nexora-node-linux-armv7.tar.gz
tar -C /tmp -xzf /tmp/node.tar.gz
install -m 0755 /tmp/nexora-node/nexora-node /var/opt/nexora/bin/nexora-node-linux-armv7
```

## Файрвол

Порт 62050 говорит по mTLS и отвергает всех, кроме панели, но выставлять его
наружу незачем:

```bash
ufw allow from PANEL_IP to any port 62050 proto tcp
```

Клиентские порты — отдельная история. Это порты назначенных ноде inbound'ов, то
есть они выбираются в панели: открывайте их после назначения шаблона, а не до.

## Ручная установка

Для сервера без выхода в интернет, хоста без systemd или панели, которой вы не
хотите разрешать исходящие запросы, — те же четыре шага вручную.

**1. Установите бинарник.**

```bash
ARCH=amd64   # или arm64, armv7, armv6, armv5, 386, s390x, riscv64
curl -fsSL -o /tmp/node.tar.gz \
  https://github.com/nexora-vpn/node/releases/latest/download/nexora-node-linux-${ARCH}.tar.gz
tar -C /tmp -xzf /tmp/node.tar.gz
mkdir -p /opt/nexora-node /var/opt/nexora/certs
install -m 0755 /tmp/nexora-node/nexora-node /opt/nexora-node/nexora-node
```

**2. Возьмите клиентский сертификат панели.** Скопируйте его со страницы
установки ноды в панели и сохраните как `/var/opt/nexora/certs/panel_ca.pem`. Это
публичный сертификат, а не секрет — нода, у которой он есть, всё равно ничего не
может сделать с панелью.

**3. Сгенерируйте собственный сертификат ноды.**

```bash
/opt/nexora-node/nexora-node gencerts -dir /var/opt/nexora/certs
```

**4. Настройте и запустите.**

```bash
cat > /opt/nexora-node/config.json <<'JSON'
{
  "listen": "0.0.0.0:62050",
  "cert_file": "/var/opt/nexora/certs/ssl_cert.pem",
  "key_file": "/var/opt/nexora/certs/ssl_key.pem",
  "client_ca_file": "/var/opt/nexora/certs/panel_ca.pem"
}
JSON

cp /tmp/nexora-node/nexora-node.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now nexora-node
```

Затем добавьте ноду в панели с адресом этого сервера и портом 62050. Панель
закрепит сертификат на первом соединении ровно так же, как после скриптовой
установки.

## Docker

```bash
git clone https://github.com/nexora-vpn/node
cd node
mkdir -p certs
cp /path/to/panel_ca.pem certs/
docker compose up -d
```

Compose-файл намеренно использует сеть хоста. Нода терминирует клиентский трафик
на портах своих inbound'ов, а те выбираются в панели уже потом — при bridged-сети
каждый новый inbound означал бы правку compose-файла и пересоздание контейнера.

## Обновление

Ноды обновляются из панели: она передаёт новый бинарник и перезапускает службу.
На самой ноде запускать ничего не нужно.

Вручную — замените бинарник и перезапустите:

```bash
systemctl stop nexora-node
install -m 0755 /tmp/nexora-node/nexora-node /opt/nexora-node/nexora-node
systemctl start nexora-node
```

Обновление не трогает сертификаты, поэтому закреплённый панелью отпечаток
по-прежнему сходится и нода возвращается без повторной регистрации.

В Docker: `docker compose pull && docker compose up -d`.

## Удаление

```bash
systemctl disable --now nexora-node
rm -f /etc/systemd/system/nexora-node.service
systemctl daemon-reload
rm -rf /opt/nexora-node /var/opt/nexora
```

Удалите ноду и в панели, иначе она продолжит считаться в вашей лицензии и висеть
как офлайн.

## Что где лежит

| Путь | Что это |
| --- | --- |
| `/opt/nexora-node/nexora-node` | бинарник |
| `/opt/nexora-node/config.json` | адрес прослушивания и пути к сертификатам — и больше ничего |
| `/var/opt/nexora/certs/ssl_cert.pem` | собственный серверный сертификат ноды |
| `/var/opt/nexora/certs/ssl_key.pem` | его закрытый ключ |
| `/var/opt/nexora/certs/panel_ca.pem` | клиентский сертификат панели — единственный принимаемый |
| `/etc/systemd/system/nexora-node.service` | unit службы |

Всё остальное — inbound'ы, outbound'ы, endpoint'ы, маршрутизация, пользователи —
приходит из панели и живёт в памяти. Больше на диске резервировать нечего.

## Диагностика

**Команда установки падает с `node binary not provisioned`.** У панели нет
бинарника для этой архитектуры. Подготовьте его на хосте панели, как показано
выше, и повторите команду со свежим токеном.

**Команда установки падает с `invalid token` или `token already used`.** Токены
установки ноды одноразовые и с ограниченным сроком. Сгенерируйте новый в панели и
скопируйте команду целиком заново.

**Нода работает, а панель показывает её офлайн.** Что-то между ними рвёт
соединение. Проверьте по порядку:

```bash
systemctl status nexora-node          # на ноде
journalctl -u nexora-node -n 50       # на ноде
nc -vz NODE_IP 62050                  # с сервера панели
```

Обычная причина — правило файрвола, не включающее адрес панели; вторая по
частоте — security group облачного провайдера.

**Нода переустановлена, и панель её не принимает.** Переустановка создаёт новый
серверный сертификат, а панель всё ещё держит закреплённым старый. Удалите ноду в
панели и добавьте заново — отпечаток будет взят заново на следующем первом
соединении.
